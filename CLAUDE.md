# AI Weekly — правила проекта для Claude Code

Автоматический русскоязычный дайджест новостей ИИ для Telegram. Запуск выпуска — команда `/run-digest`
(оркестратор описан в `.claude/commands/run-digest.md`), субагенты — в `.claude/agents/`.

## Разделение ответственности
- **Python-скрипты** (`scripts/`) — всё детерминированное: окно сбора, RSS/API, дедуп по URL, проверка ссылок,
  нарезка под 4096, валидация HTML, отправка в Telegram, состояние. Покрыты тестами (`python -m pytest`).
- **LLM-агенты** — только отбор, проверка смысла и тексты. Общение между ними — через файлы `runs/<run_id>/`.
- **Главная сессия** — оркестратор: не пишет тексты и не ищет новости сама.

## Жёсткие правила
1. Никаких выдуманных фактов: у каждой новости — ссылка на первоисточник, каждый факт — из `factcheck.json`.
2. Тексты — своими словами, без копирования чужих постов и статей.
3. Секреты (`TELEGRAM_*`) — только из переменных окружения / `.env`. Не печатать, не логировать, не коммитить.
   Не выполнять `env`, `printenv`, `cat .env`, `echo $TELEGRAM_BOT_TOKEN`.
4. Повторный запуск не публикует дважды — это гарантирует `state/published.json`; не редактировать его вручную.
5. Сомнение → не публиковать, отправить отчёт админу.
6. Пейволлы, капчи и robots.txt не обходить.

## Конфигурация (код не трогать для этих изменений)
- `config/watchlist.yaml` — компании и продукты, разделы, хэштеги.
- `config/sources.yaml` — RSS/API; `config/tg_sources.yaml` — Telegram-каналы.
- `config/format.md` — формат выпуска (разделы A–G). Если файла нет — используй шаблон:
  заголовок «AI Weekly #N · даты» + 3 главных события; разделы по компаниям; «Новое вне списка»;
  «Исследования и open-source»; «Слухи»; финал — вывод недели и хэштеги.
- `config/schedule.yaml` — дни/время, режим dry-run/live, пороги.

## Команды
```bash
python -m pip install -r requirements.txt
python -m pytest -q                                   # тесты скриптов
python scripts/pipeline.py init --kind weekly --dry-run
python scripts/tg_publish.py --check                  # проверить бота и чаты
python scripts/pipeline.py cron                       # cron-строки для расписания
```

## Git
Состояние (`state/`, `archive/`, `runs/<run_id>/`) коммитится скриптом `pipeline.py checkpoint`
в текущую ветку (в облачном запуске — в `main`). Код и конфиги в ходе выпуска не меняются.
